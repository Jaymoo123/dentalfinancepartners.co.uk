# Lead engine (dry run)

The distribution engine around the estate's verified enquiry flow. Classified leads are offered to the whole pool of buyer firms as redacted email pings, each carrying the enquiry in the enquirer's own words with identifiers stripped; firms claim on a first come, first served basis up to the claim cap (shared), or exclusively at 3x the price, which locks the lead if no firm has claimed yet (the race decides; see docs/LEAD_PRICING.md). Claims run in two independent lanes: the accounting lane (capped, where exclusivity and cascade live) and the additive adjacent lane (also capped, at 3), so an adjacent claim never consumes an accounting slot and an exclusive accounting lock leaves the adjacent lane open. A lead's price is fixed at its first claim, so later shared claimants pay the same. There is no last-call reprice: a lead holds its price while unclaimed, and after 48h fully unclaimed it cascades to the adjacent professions lane or the raw batch. Every delivery is logged per firm and pivoted into per-firm invoices on the 1st of each month, payable by bank transfer within 14 days. Credits apply to exclusive claims only. Everything here is dry-run only: pings, deliveries and invoices are rendered to local files, and any action that would send an email or create a payment prints a `[STUB] would ...` line instead. Python 3 stdlib only, no network code anywhere.

## File map

```

config/standard_terms.md     standard terms, reproduced verbatim everywhere they appear
docs/CLASSIFY.md             tiering rubric + classification prompt
docs/PRICE_SHEET.md|.html    buyer one-pager, GENERATED by build_price_sheet.py

lead_engine/
  data/firms.csv             buyer pool (signed-agreement date + active status)
  data/leads.csv             enquiries with tier, status, ping timestamps
  data/deliveries.csv        per-firm delivery log (the billing source of truth)
  templates/                 ping, delivery, invoice ({{TOKEN}} substitution)
  scripts/tiers.py           shared helpers: config, CSV, templates, terms, lanes
  scripts/test_lanes.py      self-check: the two lanes stay independent (sandbox copy, never touches data/)
  scripts/test_redaction.py  self-check: alert redaction removes every identifier shape
  scripts/classify_stub.py   demonstrates the CLASSIFY.md JSON pipe shape
  scripts/route.py           ping the active pool for one lead
  scripts/claim.py           simulate a firm claim (cap enforced, delivery rendered)
  scripts/decay.py           48h cascade pass, injectable clock
  scripts/invoice_run.py     monthly per-firm invoice pivot, credits netted
  scripts/stats.py           one-screen monthly summary
  scripts/build_price_sheet.py  regenerates docs/PRICE_SHEET.md + docs/price-sheet.html
  outbox/                    rendered pings + deliveries (gitignored)
  invoices/                  rendered invoices per YYYY-MM (gitignored)
```

## Running the scripts

All from the repo root. `--dry-run` is the default and only mode.

| Command | What it does |
|---|---|
| `python lead_engine/scripts/classify_stub.py [--all] [--message "..."]` | prints the strict classification JSON (stub of the docs/CLASSIFY.md prompt) |
| `python lead_engine/scripts/route.py <lead_id> [--lane accounting\|adjacent]` | renders redacted pings to outbox/ for every active firm that has signed the agreement and can claim on that lane, at that lane's price; the ping carries the redacted enquiry; the accounting ping stamps last_ping_at, the adjacent ping does not |
| `python lead_engine/scripts/claim.py <lead_id> <firm_id> [--exclusive] [--adjacent]` | shared claim up to that lane's cap at the price fixed by the lane's first claim; `--exclusive` locks the accounting lane at 3x if no firm has claimed it yet; `--adjacent` claims the adjacent lane (also capped) at the flat adjacent price |
| `python lead_engine/scripts/decay.py [--now ISO]` | fully unclaimed leads only: cascade to adjacent, or raw batch if unverified, at 48h (threshold from config) |
| `python lead_engine/scripts/invoice_run.py YYYY-MM` | one invoice HTML per firm to invoices/YYYY-MM/, credits as negative lines, rows marked invoiced |
| `python lead_engine/scripts/stats.py [--month YYYY-MM]` | leads by tier x status, claim rate per tier, revenue billed vs delivered |
| `python lead_engine/scripts/build_price_sheet.py` | regenerates the price sheet from config + CLASSIFY.md |
## End-to-end dry run (verified)

Runs against the seed data as checked in. To re-run from scratch first reset the seeds: `git checkout -- lead_engine/data`.

```
python lead_engine/scripts/classify_stub.py --all
python lead_engine/scripts/route.py L001
python lead_engine/scripts/claim.py L001 F001
python lead_engine/scripts/claim.py L001 F002 --exclusive
python lead_engine/scripts/claim.py L001 F002
python lead_engine/scripts/claim.py L001 F005
python lead_engine/scripts/claim.py L001 F003
python lead_engine/scripts/claim.py L002 F001 --exclusive
python lead_engine/scripts/claim.py L002 F002
python lead_engine/scripts/decay.py --now 2026-08-13T11:00:00
python lead_engine/scripts/claim.py L005 F001
python lead_engine/scripts/claim.py L005 F002
python lead_engine/scripts/invoice_run.py 2026-08
python lead_engine/scripts/stats.py --month 2026-08
python lead_engine/scripts/build_price_sheet.py
```

What each step proves (seeds: L004 carries two shared claims, one with an invalid shared-credit flag; L007 is exclusively delivered to F003 with a valid credit; F003 is active but has NOT signed the agreement; F004 is adjacent-lane and paused):

1. `classify_stub --all`: strict JSON per lead matching the CLASSIFY.md output shape.
2. `route L001`: redacted pings (txt + html) land in outbox/ for the three signed accounting firms, showing the shared price (£85), the exclusive price (£255) and the enquiry in the enquirer's own words with names, numbers, emails, postcodes, links and company names stripped. F003 is skipped with `skipping 1 active firm(s) with no signed agreement`. No contact details and no unredacted message in any ping. L001 stamped fresh.
3. `claim L001 F001`: shared claim accepted at £85, accounting slot 1 of 3.
4. `claim L001 F002 --exclusive`: rejected, non-zero exit (a shared claim already exists, so exclusivity is gone); the message quotes the shared slot at £85 instead.
5. `claim L001 F002` then `F005`: shared claims at the same £85 (price fixed at first claim); the third marks L001 delivered_full.
6. `claim L001 F003`: rejected, "F003 has not signed the data sharing agreement", non-zero exit. The signature gate blocks the claim before the cap is ever reached.
7. `claim L002 F001 --exclusive`: the exclusive claim wins the race: charged £120 (3x £40), lead locked, delivered_full, delivery email carries `Basis: Exclusive (no other accountant receives this lead)`.
8. `claim L002 F002`: rejected, "the accounting lane on L002 is exclusively locked by F001", non-zero exit.
9. `decay --now 2026-08-13`: L005 and L006 (verified, fully unclaimed, past 48h) cascade to the adjacent lane at £35; L003 (unverified) becomes raw_batch; L001, L002 and L004 are skipped because a claimed lead never cascades. No price drops anywhere: there is no last call.
10. `claim L005 F001` then `F002`: both charged the full £85 card price, because an unclaimed lead never gets cheaper.
11. `invoice_run 2026-08`: one invoice HTML per firm, credits as negative lines, `WARNING: credit on shared claim L004/F002 ignored` (credits apply to exclusive claims only), refs like `ATL-2026-08-F001`, and `[STUB] would email ... invoice` per firm.
12. `stats --month 2026-08`: 7 leads by tier x status, claim rates counting an exclusive lock as all 3 slots (advisory 8/9, standard 5/9, essential 0/3), delivered £625 net of £255 exclusive credits.
13. `build_price_sheet`: docs/PRICE_SHEET.md and docs/price-sheet.html regenerate with shared · exclusive prices per accounting tier.
