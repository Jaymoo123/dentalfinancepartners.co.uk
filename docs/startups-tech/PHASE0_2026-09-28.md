## What I could not do and why

- **No header, footer or nav anywhere in the codebase.** `layout.tsx` renders `{children}` with
  no chrome; `siteConfig.nav` (`config/site.ts:27`) is defined but never imported anywhere
  (`grep -rln "siteConfig.nav\b" web/src` = no match). This is bigger than section 4's framing
  ("header call-to-action where the site has none at any width") assumed — there is no header to
  add a CTA to. The fix that exists in the codebase is adopting the shared `PageShell` +
  `SiteHeader` + `SiteFooter` kit, exactly as crypto and Medical do (`crypto/web/src/app/
  layout.tsx`), which is the design port itself (D1: 0 `web-shared/design` imports, 0
  `port-startups-tech-*` tags). The task brief for this pass explicitly notes "the design port is
  phase 1", so I did not attempt it under phase 0 and instead flag it here as the top structural
  item. Footer "Book a consultation" (section 4 bullet 4) is moot for the same reason: no footer
  exists to carry that link.
- **Mini-capture ids** (`mobile_tool`, `calc_result_form`, `resource_block`,
  `blog_short_resource`): only 3 of 7 present (`calc_page_footer`, `inline_mini`, `calc_result`).
  Not added; would need new placements decided (which pages get `mobile_tool` vs
  `resource_block`), a design-adjacent call better made alongside phase 1.
- **Service + BreadcrumbList schema on `/for/*` and `/services/*`**: only `FAQPage` renders today
  (confirmed by the wave-2 reader, G3). Not added this pass; would use the same shared schema lib
  as the Organization fix, Medical's `/for-gps` is the reference, left as a follow-up given time.
- **Webfont**: body computes to the system stack, no `next/font`/`geist/font` import anywhere.
  Per the brief, flagged rather than fixed, since loading a font is design-port scope.
- **`/services` and `/for` hub-list pages**: added a `LeadCTAPanel` to both (not explicitly
  required by section 4's literal page list, but consistent with "every money page" and cheap to
  add given the panel already existed for the slug pages).
- Did not touch the 4-step `detail_capture_t0` nurture sequence's `delayHours` (`0,24,48,168`):
  it does not match the specific cumulative array the brief named, and no replacement mapping was
  given for a 4-step sequence.
