## 0. Counting method, stated before any number

- **Unit measured: repo source files.** File counts and occurrence counts are reported
  separately and each row says which. No built stylesheet and no rendered Next.js HTML
  was counted, so neither the one-line-CSS undercount nor the RSC-payload double-count
  applies to any figure below. Nothing here was derived from a browser or a build.
- Occurrence counts use `grep -rhoE <pattern> <paths> | wc -l` (or `| sort | uniq -c`),
  never `grep -c`. File counts use `grep -rl ... | wc -l`.
- Site surface measured: 14 blog markdown files (`ecommerce/web/content/blog/`),
  29 `page.tsx` routes, 4 calculators + 4 test files
  (`src/lib/calculators/tools/`), `src/data/{services,for,vat}.ts`, the four research
  JSON/CSV files under `src/data/`, `src/config/`, `src/lib/schema.ts`,
  `src/lib/calculator-schema.ts`, and `ecommerce/niche.config.json`.

### (e) REPRESENTATION, established before searching

Asked first what form the token takes in this site's actual bytes:

```
grep -rl '£' src content | wc -l          -> 31 files (literal match works)
grep -rn 'u00a3\|\\u00A3' src content     -> 0 hits
grep -rn '&pound;' src content            -> 0 hits
```

**`ecommerce` stores `£` as a literal UTF-8 pound sign (C2 A3), not a unicode escape and
not an HTML entity.** Literal grep is sound on this site. (`&minus;` IS used as an entity
inside blog HTML tables, so a literal `-` grep misses subtraction signs there; the
arithmetic rows below were read, not grepped.) All money/percent sweeps below therefore
used `£[0-9][0-9,.]*|€[0-9][0-9,.]*|[0-9]+(\.[0-9]+)?%` against literal bytes, returning
**1,104 numeric-token occurrences across the measured source**, deduplicated to 232
distinct values for manual reconciliation against the two ground-truth files.
