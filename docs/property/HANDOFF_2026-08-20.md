## 4. Discipline that made the last two batches work (repeat it)

- **Fresh pulls before conclusions**: `scripts/_fresh_gsc_bing_pull.py` (site totals),
  GSC API page+query (paginated; domain property `sc-domain:propertytaxpartners.co.uk`,
  filters cannot OR), Bing `GetPageQueryStats` per URL (Bing contributed 59% of the CGT
  query universe). Never conclude from stored `gsc_query_data` (sampled, ~20x under).
- **Writers**: Opus only, pack/brief as the whole world, autonomy clause, additive-only on
  EXTEND (protected elements byte-identical), one runnable verification per claim, decline
  rather than guess any figure not in `house_positions.md`, coverage note per page.
- **QA**: two Opus tracks (adversarial factual vs house positions; editorial vs the
  cluster language spec) + a final verification read after any structural fix. Expect
  ~half the pages to come back must_fix; that is the QA working, not failing. Wrong facts
  found in PROTECTED/pre-existing copy are back-patched under the factual-correction
  carve-out, recorded in the page's coverage note.
- **Deterministic gates before commit**: equity gate (`--cluster <name>`), frontmatter
  lint, link audit (0 hard), word gate, voice scan (clean/minor; letting relief showed an
  EXTEND page can sit 0.2 under the threshold — check margins before adding words), tsc,
  vitest incl. goldens, prod build (from `Property/web`, not repo root), dependency
  closure, predeploy gate with the batch's qa_verdict. Verdicts recorded LAST (hash-keyed;
  the CGT batch had to re-record after a 1-char meta trim).
- **Known costs/limits**: DataForSEO ~$6 left ($0.50/cluster harvest); Serper OUT of
  credits (no live SERP single-query claims — say so in dossiers); CI meta limits 60/155.
- **Language spec is measured per cluster, never copied** from the last one (CGT's
