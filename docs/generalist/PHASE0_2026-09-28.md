## 7. Design fixes (from the wave-2 reader pass)

- **Four unlabelled mini-calculator inputs**: not the CalculatorTabs/
  PremiumCalculator widget (`components/calculators/premium/ui/Field.tsx` was
  already fully labelled) — traced to
  `components/calculators/EmployerNICalculator.tsx:176-198`, the bespoke
  Employer NI tool. Its Role/Gross-salary `<label>` elements had no `htmlFor`,
  so screen readers never associated them with the inputs despite being visibly
  labelled. Added `htmlFor`/`id` pairs (`employee-role-${id}`,
  `employee-salary-${id}`).
- **Weakest focus ring of the four sites**: `components/forms/LeadForm.tsx:13`
  `fieldClass` only changed border colour on focus
  (`focus:outline-none`, no ring). This is a site-local class, not
  `packages/site-styles` (that's the shared agent's separate fix for the shared
  components) — added `focus-visible:outline focus-visible:outline-2
  focus-visible:outline-offset-2 focus-visible:outline-orange-500`.
- **D6 StatsCounter 0-for-non-numeric bug**: `web/src/app/page.tsx:111-114`
  `heroStats` used a narrower regex and no guard than `/services`' `HERO_STATS`
  (`web/src/app/services/page.tsx:51-57`). Homepage mapper rewritten to match
  `/services`' guarded version exactly (falls back to `{target: 0, suffix:
  value, label}` for a non-digit-leading value instead of coercing to 0).
- The `enquiry_ref` honeypot inputs (`LeadForm.tsx:190-191`,
  `DetailsForm.tsx:148-155`, `SpecialistWidget.tsx:447`) are intentionally
  `aria-hidden="true"`/off-screen — correctly excluded from the accessibility
  tree already, not a defect, left unchanged.
