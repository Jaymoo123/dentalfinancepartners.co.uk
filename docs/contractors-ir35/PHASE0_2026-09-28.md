## 4. Lead kit

- **Blog category CTA (L10, dead code — fixed)**: `BlogPostRenderer.tsx` imported
  `ctaCopyForCategory` and now calls it with `categorySlug`, falling back to the generic
  `niche.blog.cta_*` copy for an unmapped slug. Previously the closing panel always rendered
  the generic `niche.blog` copy; `ctaCopyForCategory`/`CTA_BY_CATEGORY` in `lib/blog-categories.ts`
  were only consumed by the `/blog/[category]` hub route.
- **Calculator result gate (L3 — fixed)**: `PremiumCalculator.tsx` — `gated` is now hard-`false`
  (was `placement === "blog" && !isConverted()`). The result renders directly under the inputs
  always; `ResultGateModal` is no longer opened (dead branch left in place, `gateOpen` never
  becomes true; removed the now-unused `isConverted` import).
- **Footer "Book a consultation" (BLOCKER — fixed)**: `SiteFooter.tsx` now passes an explicit
  `companyItems` override (About/Contact/Locations unchanged, "Book a consultation" ->
  `/contact#book`) instead of the kit's `DEFAULT_COMPANY_ITEMS`, which points at `/book`.
  `/book` needs a signed lead token (`app/book/page.tsx`) and the wave-2 read confirmed it
  renders zero `<form>` elements without one. `/contact#book` is the existing anchor around
  `LeadForm` on the contact page (`app/contact/page.tsx:93`).
- **Booking-page wording**: already correct per the brief's own worked example
  ("An accountant will call you then, no obligation." in `BookingPicker.tsx`/`/book` copy) —
  no change needed there; this is the wording the addendum says the other three sites (Property,
  care, charities) should adopt.
- **Sticky CTA (checked, not a bug)**: `StickyCTA.tsx` is mounted unconditionally in
  `PageShell.tsx`. It is absent from the DOM at capture time because it is deliberately
  scroll-gated (`SCROLL_THRESHOLD = 500px` or 25% of page height, per the file's own "Visibility
  rules" comment) and session-dismissible. The wave-2 reader's screenshot pass did not scroll,
  so it never triggered. This is documented intended CRO behaviour (owner decision, "intent-aware
  personalisation is ON unconditionally"), not a defect; left unchanged.
- **Real focus-ring BLOCKER (found independently, fixed)**: the wave-2 reader flagged "no
  visible focus indicator on the first form field" on `/contact`. Root cause:
  `LeadForm.tsx` and `DetailsForm.tsx` both defined their input class string with
  `focus:outline-none` and no replacement ring. Both now use the shared local `focusRing`
  constant (`focus-visible:outline-[var(--focus-ring)]`, same token the buttons already use,
  guarded by `focus-ring.test.ts`). Other `focus:outline-none` sites found by grep
  (`PremiumCalculator.tsx`, `ResultGateModal.tsx`, `BlogListWithSearch.tsx`,
  `BlogPostRenderer.tsx`, `SpecialistWidget.tsx`, `admin/analytics/login`, `locations/[slug]`)
  were not individually checked for a missing replacement ring; flagging as a residual check.
