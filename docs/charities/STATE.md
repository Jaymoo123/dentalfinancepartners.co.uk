### What zero pre-port `data-cta` means for the kit header props

The sweep counts **0 `data-cta` across all 66 sitemap URLs**, so there is no pre-port
`data-cta-goal` or `data-cta-placement` to preserve on any crawled route, and no live
`cta_click` history for this site to split at cutover.

1. Because nothing is being preserved, the port **introduces** these values rather than
   carrying them. `SiteHeader.ctaContactGoal` and `SiteHeader.ctaMobilePlacement` must
   therefore be **passed explicitly** (recommended `"contact"` and `"header_mobile"`), so
   the value is a decision with a receipt instead of Property's literal inherited by
   accident. The mobile placement is the easy one to miss: the drawer renders only when
   open, so no SSR crawl and no source review will ever see it. Verify it in the shipped
   client bundle.
2. The count going from 0 to non-zero on every route after phase 1 **is expected and is
   not a regression.** On this site the absence of a rise would be the alarm.
3. T22, the segmentation-rewrite trap, **cannot fire here**, because there is no prior
   series to rewrite.
4. Consequently there is **no before-and-after CTA funnel comparison to make**. Any
   post-cutover read of `vw_cta_performance` for `charities` is a new series starting at
   the cutover and must never be read as a delta. What does have history, and what the
   cutover read should use, is lead volume and form-submit rate.
5. **One caveat to "zero":** there is exactly one real pre-existing triple on the site,
   `data-cta="thankyou-return-article"` / `data-cta-placement="thank_you"` at
   `charities/web/src/app/thank-you/page.tsx:107-108`. It is absent from the sweep because
   `/thank-you` is noindex and not in the sitemap, and it is conditional on a `return`
   query param so no crawl would surface it either. It **must survive the port
   byte-identical**, proved by grep and by curling the route with the param set.

## Known live defects still open on this site

These are **phase 1 and 2 work, not phase 0 failures**. Phase 0 measured them; it did not
own them.

- **`prose` is a dead class on this site.** All 24 blog posts and all 8 guides render with
  `class="prose"` while the shipped stylesheet contains **zero `.prose` rules**, because no
  typography plugin is installed (`charities/web/package.json` has no typography entry, and
  the served stylesheet returns 0 matches for `.prose`). Confirmed on live production. The
  article bodies are unstyled today. Content is intact and full length; only the styling is
  absent.
- **`section-label` is a dead class name.** It carries no CSS rule anywhere in the repo or
  in the shipped stylesheet, so every instance inherits `--ink`. One instance, at
  `src/app/page.tsx:690`, sits inside a `bg-[#0f2e24]` section and measures **1.22**, which
  is effectively invisible on the live site. Either define the class or delete it; do not
  leave it.
- **8 public `text-neutral-400` instances measure 2.59** against a 4.5 floor.
- **This is estate-wide, not a charities problem.**
  `docs/_engines/ESTATE_PROSE_SWEEP_2026-09-13.md` records **161 live, user-visible
  blog and guide pages across 10 deployed sites** carrying the same dead-`prose` defect.
