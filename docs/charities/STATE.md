### What zero pre-port `data-cta` means for the kit header props

The sweep counts **0 `data-cta` across all 66 sitemap URLs**, so there is no pre-port
`data-cta-goal` or `data-cta-placement` to preserve on any crawled route, and no live
`cta_click` history for this site to split at cutover.

1. Because nothing is being preserved, the port **introduces** these values rather than
   carrying them. `SiteHeader.ctaContactGoal` and `SiteHeader.ctaMobilePlacement` must
   therefore be **passed explicitly** (recommended `"contact"` and `"header_mobile"`), so
   the value is a decision with a receipt instead of Property's literal inherited by
   accident. The mobile placement is the easy one to miss: the drawer renders only when
   open, so no SSR crawl and no source review will ever see it. Verify it in the shipped
   client bundle.
2. The count going from 0 to non-zero on every route after phase 1 **is expected and is
   not a regression.** On this site the absence of a rise would be the alarm.
3. T22, the segmentation-rewrite trap, **cannot fire here**, because there is no prior
   series to rewrite.
4. Consequently there is **no before-and-after CTA funnel comparison to make**. Any
   post-cutover read of `vw_cta_performance` for `charities` is a new series starting at
   the cutover and must never be read as a delta. What does have history, and what the
   cutover read should use, is lead volume and form-submit rate.
5. **One caveat to "zero":** there is exactly one real pre-existing triple on the site,
   `data-cta="thankyou-return-article"` / `data-cta-placement="thank_you"` at
