# Handoff, 14 August 2026

Fresh agent: read this file top to bottom. No conversation context needed.

## The model, in the owner's words

1. Tier the leads.
2. Redacted message goes to the pool.
3. The pool selects.
4. Owner sends the full details.

That is the whole thing. Everything below is how it is implemented and what is still open. **Do not add mechanics to this model.** Last call (a reduced price after 24 hours) was built and then removed on the owner's instruction because it added state without adding value. Treat that as the standard: if a feature does not serve one of those four lines, it probably should not exist.

## Where each line lives

| Line | Implementation |
|---|---|
| Tier the leads | `docs/CLASSIFY.md` is the rubric. Grades are stored on the lead (`lead_value_scores.case_tier`, `case_type`, `intent_line`). Every lead that existed at the 14 August grading run is graded; leads that arrive after it are not, and grading them is a manual step. |
| Redacted message to the pool | `lead_engine/scripts/route.py` renders an alert per firm into `lead_engine/outbox/`. `tiers.redact()` strips names, phones, emails, postcodes, links and company names. Live equivalent: `redactMessage()` in `Property/web/src/lib/leads/offer-teaser.ts`. |
| The pool selects | `lead_engine/scripts/claim.py`. Up to 3 accounting firms, or one exclusive claim at 3x. A second, separate lane of up to 3 non-accounting firms. |
| Owner sends the full details | `claim.py` renders the delivery from `lead_engine/templates/delivery.*`, carrying contact details, the unredacted message and the lawful-basis notice. Everything is dry run: nothing sends email and no invoice is sent. |

Prices and caps come from `config/tiers.json`. Nothing is hardcoded. Buyer-facing terms come from `config/standard_terms.md`, reproduced verbatim wherever they appear.
